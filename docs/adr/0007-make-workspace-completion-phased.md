# Make workspace completion phased

`done` used to validate, integrate, and clean up one Workspace repository at a time. A failure in a later repository left earlier ones already merged and their worktrees deleted, and the next `done` then failed on the missing worktrees, so the Workspace could never complete. Completion is now phased across all repositories: validate everything read-only, run `pre_done`, integrate every selected repository, and only then clean up every worktree and archive. A failed integration stops before cleanup, keeps every worktree, and rolls back the half-integrated Source checkout on a best-effort basis.

Integration progress is recorded as `merged` and `pushed` events carrying the repository and the Workspace branch (or target) head, so a retry skips what already succeeded but re-integrates a branch that has moved since. We rejected rolling back already-integrated repositories because a push cannot be undone, and rejected re-integrating on every retry because a squash cannot be detected as already applied and may conflict once the target has moved.

`zootree merge` integrates without any of this state: it neither cleans, completes, runs hooks, nor records progress, so it can be repeated freely and a later `done` will integrate again (a no-op for an unchanged squash). Adding a hook stage for it would widen the hook configuration surface and is left for a separate decision.

Both commands check the Source checkout's current branch against the resolved Target branch for each repository they will integrate. The CLI presents all required switches together before the first hook or Git mutation, since discovering a switch midway would leave earlier repositories integrated even if the user declined. An interactive answer authorizes the listed switches. If a hook changes a checkout, integration stops before switching it from a newly observed branch. Scripts can use the global `--yes` to authorize all branch switches and the uncommitted-changes prompt in `cancel`. A matching worktree can still be reused during Reopen, so overwriting it requires the separate authorization defined in the [Reopen ADR](0003-reopen-archived-workspaces.md).

Three consequences are deliberate. `--force` never excuses a missing worktree of a repository that should be integrated, because that would silently leave it out; leaving it out takes an explicit `--skip-repo`. A rebase that succeeds but whose follow-up fast-forward fails is not rolled back: the rebased Workspace branch is valid work and rebasing again is a no-op, whereas resetting it could discard commits made in the worktree meanwhile. Repositories that are cleaned but not integrated run `pre_remove` with their configured target branch (or none), since ADR-0005 provides `ZOOTREE_TARGET_BRANCH` only when one is available and resolving it would mean inspecting a Source checkout that is not being integrated.
