# Reopen archived Workspaces from recoverable Git history

`zootree reopen [name]` returns a `done` or `canceled` Workspace to `in_progress` by recovering every repository worktree before changing lifecycle state. Reopen is deliberately separate from first-time `start` and environment-only `open`: it preserves the Workspace's task branch and target branches while allowing missing local task branches to be recreated from recoverable remote history, each repository's current revision, or an explicitly selected base branch.

Reopen builds and validates a complete recovery plan before making changes. An existing local task branch is preferred; otherwise an existing remote-tracking task branch is used to recreate it without an implicit fetch, preferring `origin` and requiring a choice when other remotes are ambiguous. If no task branch remains, interactive use asks for a base per repository, while non-interactive use supplies a global `--from current` default and optional `--from <repo>:<branch>` overrides. A selected base recreates the original task branch but never changes the stored target branch. A task branch checked out by another worktree is reported as a conflict rather than moved or adopted.

An occupied canonical worktree path always requires an interactive reuse-or-overwrite decision. A valid matching worktree may be reused; other occupied paths require overwrite authorization or cause the command to stop. Non-interactive `--overwrite <repo>` is explicit authorization to remove that repository's path, including uncommitted and untracked content. Prompts identify the exact path, warn about irreversible loss, and default to declining. Destructive targets remain constrained to the resolved canonical repository worktree path and must never follow a symlink or remove a registered source repository.

New and overwritten worktrees receive the normal `copy_files` setup and `post_create` hook; reused worktrees do not. After all worktrees succeed, Reopen appends a `reopened` event whose detail records the previous status, moves the Workspace to `in_progress`, runs the existing `post_start` hook, and activates its Terminal environment unless `--no-multiplexer` was requested. `--skip-hooks` skips `post_create` and `post_start`, but not file copying. `--dry-run` performs planning only.

Failures before the lifecycle transition leave the Workspace archived, write no event, and best-effort remove worktrees created by the attempt; content deleted by an explicitly authorized overwrite cannot be recovered. A `post_start` or Terminal environment activation failure is partial success: the Workspace remains `in_progress`, and activation is not attempted after a failed `post_start`. A surviving Terminal environment may be adopted when worktrees are reused, but any overwrite first requires that environment to close successfully—even with `--no-multiplexer`—because its shells may otherwise retain deleted working directories. If later recovery fails, zootree does not try to reconstruct that closed environment.
