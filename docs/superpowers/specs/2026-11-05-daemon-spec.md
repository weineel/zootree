## Problem Statement

zootree 目前只有命令行和终端 TUI。每次命令都是一个一次性进程,没有常驻部分。随着 Orca 看板、将来的 Web 页面等 Consumer 出现,这带来几个问题:

- Consumer 想知道 Workspace 的状态变化,只能反复启动 zootree 进程轮询。Orca 的轮询已经造成过实际故障:多个进程同时启动时抢着建日志符号链接,偶发失败。
- 没有任何跨进程的并发保护。两个进程同时对同一个 Workspace 做 done 和 cancel,会让 worktree 与配置状态不一致。ADR-0003 明确把锁推迟为独立设计。
- start、done、reopen 的 hook、复制文件、push 都可能长时间运行,但调用方完全看不到进度,只能干等。
- 每个 Consumer 都要自己解析命令行输出或 `--json`,没有统一的、可订阅的接口。

## Solution

给 zootree 增加一个**可选**的本机 Daemon,让 CLI、Orca、将来的 Web 页面这些 Consumer 通过同一套 API 读取状态、发起操作、订阅变化。

- Daemon 是可选的。没有它,CLI 照旧在进程内工作;所有修改状态的路径都先取按 Workspace 的跨进程锁并原子写,所以 CLI 和 Daemon 可以安全共存,用户手动编辑 Workspace 文件也仍然受支持(ADR-0006)。
- 所有修改状态的请求立即返回一个 Operation 标识。进度、日志和最终结果可以通过事件流和查询获得。
- 状态变化通过带序号的事件流推送,支持断线续传。
- Orca 只支持 Daemon,不再保留命令行轮询;Web 页面本期不实现,只预留扩展点。

## Implementation Decisions

- **定位**:Daemon 可选,命令行保持一等公民。正确性依赖锁和原子写,不依赖 Daemon 存在。普通命令行命令不自动启动 Daemon;启动者是 Orca、将来的 Web,或显式的 `daemon start`。Orca 只支持 Daemon。
- **并发保护(已落地)**:start、done、cancel、reopen、add-repo 先取按 Workspace 的跨进程锁,已被占用时立即失败而不是等待;所有 Workspace 保存统一为原子写。
- **服务层**:把 start、done、cancel、reopen、create、add-repo、prune 等生命周期逻辑抽成与 clap 参数类型、打印、终端提示无关的服务函数,输入是请求对象,输出是结果对象。命令行处理函数变成薄适配层,Daemon 调用同一批服务函数。服务层内部遇到缺参数必须报错,不得进入交互。
- **事件回调**:服务层通过一个事件接口报告开始、步骤、日志行、警告和结束。命令行的实现把它们打印到终端,Daemon 的实现把它们广播给订阅者。
- **外部命令执行**:`CommandRunner` 需要支持逐行转发输出,同时保持现有的整体捕获用法与测试替身可用。
- **环境注入**:子进程环境来自请求携带的白名单环境快照(PATH、SSH 认证、zellij 和 herdr 的调用者上下文),而不是 Daemon 自己的环境。终端环境的上下文判断需要一个注入点。
- **客户端本地动作**:终端环境的前台 attach、打开编辑器、配置编辑永远是命令行本地行为;Daemon 对"激活终端环境"只做对账和创建,并返回需要 attach 的信息。
- **运行形态**:同一个二进制的 daemon 子命令。异步运行时和 HTTP 服务承载传输,zootree 核心保持同步,每个操作在阻塞线程里执行。
- **生命周期**:单实例,靠锁文件加 socket。没有客户端连接且没有进行中的 Operation 约 10 分钟后自动退出。提供 start、stop、status 子命令。仅支持 macOS 和 Linux。
- **传输与协议**:HTTP 加 JSON 的请求/响应,SSE 作为事件流,监听权限为 0600 的 unix socket。发现文件(进程号、端点、令牌、启动时间、协议版本)权限为 0600。每个请求携带令牌。
- **存活判断**:三态:确认在监听、确认未监听、无法判断。仅连接被拒绝或端点不存在才算确认已死;超时和权限错误视为无法判断,不得据此删除端点。清理时只清理自己创建的东西。
- **版本与兼容**:信封带协议版本、最低兼容客户端版本和能力字符串列表。响应对未知字段宽容。新增能力用能力字符串门控。删除方法、改变字段语义或鉴权方式才升协议版本。不同大版本的 Daemon 用不同的端点名共存。错误是稳定的字符串错误码。
- **资源与接口**:Workspace 的列表、详情、创建;对单个 Workspace 的 start、done、cancel、reopen、add-repo(返回 Operation);已归档 Workspace 的删除;Registered repository 的列表、注册、移除;agent 目录;Operation 查询;事件流;状态(版本、能力、进程号、启动时间)。Workspace 与 repo 的响应体沿用已发布的 `--json` 结构。
- **Operation**:所有修改请求立即返回 Operation 标识。Operation 记录只存内存,保留最近 100 条或 24 小时,Daemon 重启后丢失。客户端断开默认不终止 Operation;显式取消才尽力中断当前子进程并走已有回滚逻辑。同一 Workspace 上已有 Operation 在跑时,第二个修改请求被拒绝,返回专用错误码和正在执行的 Operation 标识,不排队;不同 Workspace 可并行。Daemon 在操作中途崩溃不尝试恢复。
- **事件模型**:一条全局事件流,事件带单调递增序号;服务端保留最近 1000 条或 10 分钟;客户端用上次序号续传,缺口过大时服务端发重新同步事件。订阅顺序为先监听、再快照、最后标记就绪。事件类型包括 Workspace 变化(带完整摘要)、Workspace 移除、Operation 开始、进度、日志、结束,以及 repo 变化。
- **外部变化检测**:有订阅者期间每 2 秒按修改时间加文件大小扫描一次相关目录,把变化转成事件。检测逻辑放在可替换的接口后面,以便以后换成文件系统监听而不改事件 API。Daemon 自己执行的操作直接发事件,不依赖扫描。
- **Web 扩展点(仅预留)**:监听器可有多种传输(目前只有 unix socket,留出回环 TCP 的位置);鉴权是独立的一层;能力列表预留 web 相关项;静态资源托管有挂载点。本期不实现 Web 页面、回环 TCP、浏览器鉴权。
- **Orca 迁移**:删除命令行执行器,改为 Daemon 客户端:读取发现文件、三态探测、按需启动 Daemon、HTTP 加事件流,去掉轮询。看板业务规则和现有测试尽量保持。版本门槛改为检查 Daemon 状态返回的协议版本和能力,zootree 发布版本为 0.2.0。二进制路径设置仍保留,用于启动 Daemon;启动失败时看板显示原因和路径输入框。
- **文档**:术语 Daemon、Consumer、Operation 写入 zootree 的领域词汇表;ADR-0006 记录"Daemon 可选"的决定。Orca 的看板 spec 需要同步更新(去掉"不引入常驻进程"和"定时轮询"的描述)。

## Testing Decisions

- **好测试的标准**:只断言外部可观察的行为,例如 HTTP 响应、事件序列、Operation 的最终结果、锁的占用与释放、文件内容。不断言内部函数调用顺序。
- **接缝一(新增,唯一的新接缝)**:Daemon 的 HTTP 接口。在进程内把 Daemon 启动在临时目录的 unix socket 上,配置目录用测试专用的临时目录,外部命令用测试替身。只通过 HTTP 请求和事件流验证:状态与列表、各生命周期请求的 Operation 结果、正忙拒绝、取消、事件序号与续传、重新同步、版本与能力、令牌校验、空闲退出规则、发现文件与存活判断。
- **接缝二(现有)**:服务层的集成测试,沿用 zootree 现有风格(临时配置目录加外部命令测试替身),覆盖抽出的生命周期函数及事件回调,包括:缺参数必须报错、环境快照被应用到子进程、逐行输出转发。命令行进程内路径与 Daemon 共用服务层,这里测过的行为不在接缝一重复。
- **并发与原子性**:锁的独占与释放、不同 Workspace 互不阻塞、读者不会读到半截文件(已有测试);再加上并发启动多个 Daemon 只会有一个成功。
- **Orca 侧**:沿用看板服务的现有测试接缝,把假的命令执行器换成假的 Daemon 客户端,验证迁移规则、失败处理、忙碌拒绝、版本门槛和 Daemon 不可用时的状态。
- **先例**:zootree 的集成测试(临时配置目录加测试替身)、日志符号链接的并发测试;Orca 的看板服务单元测试。跨版本互测等 zootree 有第二个带 Daemon 的发布版本后再引入。

## Out of Scope

- Web 页面本身,以及回环 TCP、浏览器鉴权、静态资源托管的实现。
- 从其他机器访问 Daemon、端到端加密、账号体系。
- Windows 支持。
- 把 Daemon 变成唯一入口,或命令行自动启动 Daemon。
- Operation 的持久化、崩溃恢复、排队。
- 文件系统监听。
- 并发与锁以外的 Workspace 配置格式变更。
- Orca 保留命令行执行器作为回退。
